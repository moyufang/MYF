##### 安装 32 位环境

因为饥荒已经是个很老的游戏了，所以需要安装一些必需的32位运行库，当然如果你上面的云服务器本身是32位的那可以直接跳过。我这里白嫖的64位的机器，所以这步必须有，不过很简单，分别复制粘贴下面这些命令执行即可。

```bash
# Step2: 预装32位环境（因为饥荒服务端依赖32位库）

apt update
apt -y upgrade

# 安装 software-properties-common 包
# 这个包提供了管理软件源的工具，比如 add-apt-repository 命令
apt -y install software-properties-common

# 添加 Ubuntu 的 multiverse 软件源
# multiverse 源包含一些版权或法律限制的软件，某些32位库可能依赖这里的包
add-apt-repository multiverse

# 让 dpkg（Debian 包管理器）支持 32 位架构（i386）
# 这样系统就可以安装和运行 32 位的软件包
dpkg --add-architecture i386

# 再次更新软件包列表，这次会包含新添加的 i386 架构和 multiverse 源的软件信息
apt update

# 安装以下 32 位运行库（关键依赖）：
#   libc6:i386        - GNU C 标准库的 32 位版本，几乎所有程序都需要
#   lib32gcc1         - GCC 的 32 位运行时库，用于支持旧版 GCC 编译的程序（如 SteamCMD 和饥荒服务端）
#   lib32stdc++6      - GCC 的 32 位 C++ 标准库，许多 C++ 程序依赖
#   libstdc++6:i386   - 与上一条类似，也是 C++ 标准库的 32 位版本（不同打包方式的变体）
sudo apt install -y libc6-i386 lib32stdc++6 lib32gcc-s1

# 安装 libcurl4-gnutls-dev 的 32 位版本
# libcurl 是一个支持多种协议的客户端 URL 传输库（HTTP、FTP 等）
# gnutls 是 GNU 的 TLS/SSL 实现，这里用于安全连接；dev 包通常含头文件，但运行时库也会被安装
# 饥荒服务端可能用 libcurl 与 Steam 主服务器通信或下载 mod
apt-get -y install libcurl4-gnutls-dev:i386

# 安装 htop —— 一个交互式的进程查看器，比 top 更直观、易用
# 方便你监控服务器 CPU、内存占用情况
apt-get -y install htop

# 安装 screen —— 终端多路复用器
# 允许你在一个 SSH 会话中创建多个独立窗口，断开连接后程序仍在后台运行
# 用来让饥荒服务器进程持久运行，即使关闭终端也不会中断
apt-get -y install screen
```
- **screen**：常用于在服务器上启动长期运行的任务。基本用法：`screen -S dst` 创建名为 dst 的会话，在里面运行启动命令，然后按 `Ctrl+A` 再按 `D` 脱离会话；下次用 `screen -r dst` 重新连接。

##### swap

如果是云服务器且内存小，开辟一块磁盘空间制作 `swap` 文件，给内核用作虚拟内存

```bash
dd -if=/dev/zero -of=$swapfile 
mkswap $swapfile
swapon $swapfile
```

##### Docker

Docker 官方也提供了一个自动脚本，可以快速完成安装：

```bash
curl -fsSL https://get.docker.com | sudo sh
docker --version
docker compose --version
```
每次使用 `docker` 命令都加 `sudo` 很麻烦，可以把当前用户加入 `docker` 用户组：

```bash
sudo usermod -aG docker $USER
newgrp docker
```
这里有一些最常用的 Docker 命令，可以帮你快速上手[](https://cloud.tencent.cn/developer/article/2621090)[](https://cloud.tencent.com.cn/developer/article/2611913?from=15425&frompage=seopage)：
- `docker pull nginx`：从 Docker Hub 拉取一个名为 `nginx` 的镜像到本地。
- `docker images`：列出你已经下载好的所有镜像。
- `docker run -d --name my-nginx -p 8080:80 nginx`：用 `nginx` 镜像创建并运行一个名为 `my-nginx` 的容器。`-d` 表示后台运行，`-p 8080:80` 意思是将你电脑的 8080 端口映射到容器的 80 端口。
- `docker ps`：查看当前正在运行的容器。
- `docker stop my-nginx`：停止名为 `my-nginx` 的容器。
- `docker rm my-nginx`：删除已停止的 `my-nginx` 容器。
- `docker exec -it my-nginx bash`：进入正在运行的 `my-nginx` 容器内部，进行调试。
- `docker system prune -a`：清理所有停止的容器、未使用的网络和镜像，释放硬盘空间。

##### 安装 steam 和饥荒服务器

确保路由器或防火墙放行了UDP 10998-10999端口
```bash
sudo ufw allow 10998:10999/udp
```

[DMP 饥荒管理平台](https://github.com/miracleEverywhere/dst-management-platform-api)

拉取最新镜像
```bash
docker pull ghcr.io/miracleeverywhere/dst-management-platform-api:latest

mkdir ~/dmp/{data,dst,klei,dmp_files,steamcmd,logs,Steam}
```

创建文件 `~/dmp/docker-compose.yml`，写入
```yml
services:
  dst:
    image: ghcr.io/miracleeverywhere/dst-management-platform-api:latest
    container_name: dmp
    restart: always
    # network_mode: host
    # 如果不使用 host 模式，需要开放 web 端口和世界的直联端口
    ports:
       - "8082:8082"
       - "11000-22000:11000-22000/udp"
    environment:
       - DMP_PORT=8082
       - DMP_IN_CONTAINER=1
       - LEVEL=info
    volumes:
      - ~/dmp/data:/root/data
      - ~/dmp/dst:/root/dst
      - ~/dmp/klei:/root/.klei
      - ~/dmp/dmp_files:/root/dmp_files
      - ~/dmp/logs:/root/logs
      - ~/dmp/steamcmd:/root/steamcmd
      - ~/dmp/Steam:/root/Steam
      - /etc/localtime:/etc/localtime:ro
      - /etc/timezone:/etc/timezone:ro
```
启动 dmp
```bash
docker compose up -d
```
之后在主机 PC 上访问 `<server_ip>:8082`，即可通过 Web 界面创建房间、添加mod、启动世界了。
